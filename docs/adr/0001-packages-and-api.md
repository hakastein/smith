# 1. Пакеты и публичный API

## Контекст

smith запускает один этап headless-агента — Claude Code или Codex — в песочнице. Потребители — сервисы на Go, у
каждого свои этапы, порядок и предметная логика: агентное ревью в CI, бот канала, помощник поддержки. Им нужно одно и
то же: запустить этап с заданием, моделью, скиллами и читаемыми путями, получить ответ, события потока и расход,
отменить этап контекстом, дать агенту команды, исполняемые на стороне сервиса, и запустить остальные этапы волны,
когда модель первого начала отвечать.

## Решение

Единица работы — этап на драйвере. Оркестрации нет: порядок и параллельность этапов — Go-код потребителя
(горутины, `errgroup`). Конфигов этапов и скриптового движка нет.

Публичные пакеты:

| Пакет | Что даёт |
|---|---|
| `agent` | Общая форма этапа: `Event` потока, `Outcome` исхода, `Telemetry` (лог, поток в `Stream`, статистика, `Responding()` — модель начала отвечать), процесс этапа `Start`/`Lines`/`Wait` и `Group` для внешних команд. |
| `drivers` | Контракт `Driver.Run(ctx, Args, *Telemetry)`, задание этапа `Args` с песочницей `Sandbox`, окружение драйвера `Setup`/`Settings`, реестр `Register`/`Get`/`Names`/`New`/`Gaps`. |
| `drivers/claude`, `drivers/codex` | Драйверы; регистрируются в `init`, потребитель импортирует нужные. |
| `broker` | Команды агента: тонкий клиент `Main` для песочницы, `Listen` — сокет этапа в своём каталоге с проверкой `allow` и Go-обработчиком потребителя. |
| `cost` | Запись этапа для отчётов о расходе, таблица, итог, `cost.json`, лимиты подписки. |
| `skills` | Скиллы этапов: встроенные в сервис и из каталогов; копия скиллов прогона, из которой драйвер ставит этапу его скиллы. |
| `redact` | Вымарывание значений секретных переменных окружения из текста, уходящего наружу. |
| `logx` | Лог прогона в stderr с отметкой времени и вымарыванием; метку строк задаёт сервис. |

`internal/launch` — то, что драйверы делают одинаково: свод потока запуска в исход, проверка бинарника, файлы запуска
(ссылки на скиллы, копия кредов, журнал сессии с вымарыванием). Потребителю это не нужно.

Знание драйвера — флаги CLI, формат потока, цены, способ песочницы — только в пакете драйвера. Общий слой получает от
драйвера готовый `Outcome`.

Событие «модель начала отвечать» — канал `Telemetry.Responding()`: закрывается началом ответа или концом этапа, так
что ждущий не висит на этапе, который до ответа не дошёл. Канал, а не колбэк: волна пишется через `select` и
`errgroup` без синхронизации в коде потребителя.

Команды агента — Go-обработчики потребителя. Сокет этапа лежит в своём временном каталоге, и строгая песочница
открывает этот каталог только своему этапу (`drivers.Args.Socket`): агент не зовёт команды через сокет соседа.
`allow` этапа — префиксы из слов любых команд: драйвер переводит их в свои правила разрешений, брокер отклоняет вызов
команды вне них кодом 2, обработчик такого вызова не видит.

## Следствия

- Два потребителя — сервис ревью и сервис поддержки на codex — закрываются одним `drivers.Args` без полей под
  потребителя: читаемые пути, сокет, схема ответа, скиллы, общий системный промпт.
- Драйвер стороннего CLI пишется на `agent` (процесс, события, исход) и регистрируется в `drivers`.
- Лог smith идёт в stderr процесса; сервис со структурным логом получает его строками.
